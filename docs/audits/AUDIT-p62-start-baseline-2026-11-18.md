## 五、下一步批次建议

**首批改为：域包插件边界底册与门**。理由：用户已裁定按领域拆插件；在建立 14 域包的命令 / 页面 / op / 资产归属底册前，任何页面资产化或 bundle 改动都可能把多个领域重新塞回同一插件。

切片前必须回答三项事实，不可直接搬目录：

1. OPC 页面当前依赖宿主 router、store、i18n 与 `@/` 共享模块，插件 iframe 通道只放行两条桥命令；
2. `domainPageRegistry.ts` 明确记录“不复用插件 `pages[]` + iframe 通道”的理由：宿主上下文缺失；
3. 可行路线要么把 OPC 页面改造成插件内自足 bundle（含 i18n / 数据请求走 SDK 桥），要么为插件页扩展受控宿主上下文能力，二者是架构裁定，不是路径替换。

因此本审计只固定启动基线；页面路线与独立仓节奏按 `PLAN-p62-domain-pack-plugins.md` 的批 0→批 1 序列推进。
