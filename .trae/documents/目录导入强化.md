# 知识库目录导入功能强化 —— 分阶段实施计划

## Context

用户要求"极大强化"知识源「从目录导入」功能（`ImportDirectoryModal` → `import_knowledge_directory`），已确认强化方向（A 格式覆盖 / B 导入交互 / C 内容智能 / D OCR 转写）并额外要求「生成 markdown 副本 / 可浏览 Wiki 视图」作为**可选开关**。交付节奏：**分阶段**，逐段验证；解析依赖：**接受外部 CLI**（沿用现有 tesseract 模式）。

现状短板（已核实）：
- 白名单硬编码 12 种类型（`knowledge.rs:42` `is_supported_knowledge_ext`），无压缩包、无排除规则
- 导入同步阻塞、无进度/预览/取消；失败仅计数，无分类与重试
- 增量同步仅 size+mtime（`knowledge.rs:2065`），无内容 hash、无移动识别
- document-parser 真实解析覆盖 txt/md/csv/html/xml/json/pdf/docx/xlsx/pptx/图片(系统 tesseract OCR)
- 索引管线四阶段（STAGE_PARSING→CHUNKING→EMBEDDING→STORING）与失败重试/进度事件已就绪，**不新建调度框架**

## 阶段 1：格式扩展 + 导入交互（本次落地）

### 1a. 白名单集中化 + 解析器扩展
- `is_supported_knowledge_ext` 从 `knowledge.rs` 收口到 document-parser：新增 `SUPPORTED_EXTENSIONS` 常量 + `is_supported_ext()`，`knowledge.rs` 委托调用，消除双源
- document-parser `extract_text` MIME 分发新增解析器：
  - `.xls/.ods` → **calamine**（纯 Rust，覆盖 xlsx 现状）
  - `.doc`（二进制 Word）→ 外部 `antiword` 命令，复用 `ocr_fallback` 的 spawn+超时模式（`lib.rs:97`），抽通用辅助 `external_command_extract`
  - `.odt` → zip 读 `content.xml`，复用现有 XML 文本抽取
  - `.rtf` → **rtf-parser**；`.epub` → zip 读 OPS `content.xhtml` 复用 HTML→文本
  - `.ipynb` → serde_json（已有）解析 cells；`.yaml/.yml` → **serde_yaml_ng**；`.toml` → **toml**
  - `.eml` → **mailparse** 取正文（`.msg` 明确不做，收益低）
  - 代码文件族（rs/py/js/ts/go/java/c/cpp/sh/sql 等）→ 走 text/plain，入白名单
- 同步扩充 `mime_from_extension()`（`lib.rs:239`）
- 新增依赖全部落在 document-parser（implementor，允许第三方依赖）

### 1b. 压缩包解包（扫描层）
- 扫描阶段对 `.zip`/`.tar.gz` 展开：依赖 **zip**（已在树）+ **tar/flate2** + **tempfile**
- 安全护栏：拒绝 zip-slip（`..` 路径）、单包 ≤200MB / ≤5000 条目、嵌套深度 ≤2；展开到 temp，导入结束清理
- 展开后条目统一走递归+白名单+排除规则；解包失败条目计入 skipped/失败

### 1c. 排除规则
- 内置噪声目录常量 `NOISE_DIRS`（node_modules/dist/.venv/build/target/__pycache__/.git 等，放 knowledge.rs 导入策略层）
- 用户 glob：**globset**，参数 `ignorePatterns`，同时作用于 import 与 sync

### 1d. 异步导入架构
- 新命令 `import_knowledge_directory_async`：立即返回 `importId`，tokio 任务执行扫描→解包→登记→入队
- 进度事件推送（非轮询）：`knowledge-import-progress`，payload `{ importId, phase: scan|unpack|enqueue|done|cancelled|failed, processed, total, currentPath }`（camelCase）
- 取消：`tokio-util::sync::CancellationToken`，AppState 挂 `Mutex<HashMap<importId, CancellationToken>>`，命令 `cancel_knowledge_import(importId)`；补 `get_knowledge_import_status(importId)` 供弹窗重开刷新

### 1e. 预览 / 报告 / 重试
- `scan_knowledge_directory`（只扫描不写库）→ `DirectoryScanResult { files: DirectoryScanEntry[], skipped, excluded }`，`DirectoryScanEntry { path, relativePath, sizeBytes, extension, mimeType }`
- `DirectoryImportOptions { recursive, extensions, ignorePatterns, conflict, unpackArchives, selectedPaths }` 替换现有裸参数
- `ImportDirectoryError` 加 `code` 字段（走错误码翻译）；`ImportDirectoryResult` 每文件状态 imported/duplicate/failed
- `retry_knowledge_import_errors(baseId, paths)`：对失败路径重走 add_document+enqueue
- UI：`SourceManager.tsx` 的 Modal 改三步向导（①选目录+排除配置 → ②scan 表格勾选 → ③进度+报告+重试），新组件放 `src/components/settings/`

### 1f. 冲突策略
- `conflict: "skip" | "overwrite"`：skip（默认，sourcePath 已存在→duplicate 跳过）、overwrite（复用 sync 现有删旧+重加路径 `knowledge.rs:2106`）

### 1g. 错误码（harness `error_codes.rs` + 11 语言 locale）
`IMPORT_CANCELLED`、`ARCHIVE_UNPACK_FAILED`、`ARCHIVE_ENTRY_REJECTED`、`DUPLICATE_DOCUMENT`、`DOCUMENT_UNSUPPORTED`、`SCAN_FAILED`

## 阶段 2（方向）：内容智能
- 增量升级：migration 加 `content_hash` 列；sync 比较 hash（touch 场景跳过）；移动识别按 hash 反查改 sourcePath
- 内容去重：导入期 hash 去重（同 hash→duplicate）；simhash 相似度去重默认关
- 智能分块：`indexing.rs` 分块函数按 markdown 标题/空行段落边界
- 元数据：parse 阶段提取 title/author/date，入库（entity 无 meta 列则 migration）

## 阶段 3（方向）：OCR / 转写强化
- OCR：tesseract 参数化 `lang` 与超时；扫描 PDF 用 `pdftoppm`（poppler）外部命令→tesseract
- 音视频转写：外部 CLI（whisper.cpp / faster-whisper），复用外部命令模式，模型路径可配置；异步+取消走阶段 1 token 机制

## 阶段 4（方向）：Wiki 可选开关
- 导入参数加 `generateMarkdown: bool`（默认关），开启后按目录结构生成 .md 副本到 vault 目录并作为 wiki 笔记登记入队；复用 index_queue 已有 `wiki → WikiVault` 容器（`index_queue.rs:348`）
