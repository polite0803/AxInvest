### B2. synthetic 兜底：保留 + 真实值优先（D4 决策）

**已决：保留（标记）。** 但「保留」不等于「现状可接受」——需分两步。

#### B2.0 先把事实说清楚（避免修错东西）

| 报告原表述               | 实际机制（已核实 `watchlist.rs:235-380`）                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「synthetic 恒 conf=40」 | 数值对，**机制不是硬编码**：`calc_confidence(0.45, 0.4, 0.4, 0.0, 1.0)` 的**输入全部来自固定默认值** → 输出恒定 40。修法是让输入用真实值，不是改常量                                  |
| 「synthetic 未标记」     | **已标记**：`RecoPick.synthetic: true` + `reasons[0]` 含「信号缺失，按现价合成」+ `risk_notes` 明写「本条为按现价合成的兜底结果」。**标记这一环不用新增**                             |
| 「按现价合成」           | `price` **是真实的**（`client.get_quote(code)`），真实且已过滤 `is_st` / `price<=0`。**不真实的只有 `entry/stop/target/position`** —— 它们 = `price × 固定系数`（系数取变量 `syn_*`） |

#### B2.1 「为什么不能为真实值」——要分两类空桶，不能一刀切

**可以用真实值，只是没做。** 判据是**同时期是否有同数据依赖的风格产出了真实候选**：

| 空桶类型             | 成因                                                                               | 能否用真实值                         | 处置                                 |
| -------------------- | ---------------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------ |
| **(a) 数据不可用型** | 拉不到 K 线 / 财务 / 资金流 → 策略短路返回 None                                    | **不能**（用真实值会因同样原因失败） | 维持固定系数兜底，**保留 synthetic** |
| **(b) 信号不达标型** | 数据拿得到，但策略条件苛刻（如 trend 要求 MA5>MA10 + 近 5 日高 ×0.97 + 量比 ≥0.8） | **能，且应该**                       | **改为真实值优先**                   |

**实证 (b) 类确实存在**：2026-09-12 批次 `short` 周期下 `capital` 产出 **20 条真实候选**、`value` 产出 10 条真实候选，而同期 `trend` 桶 **20 条全 synthetic**。`capital` 依赖行情 + 资金流，它出得来 ⇒ **行情链可用** ⇒ `trend` 空桶属 (b) 类。

#### B2.2 改动方案

1. **在 `scan_synthetic_one` 内先做一次真实值尝试**：
   - 拉 K 线（`kline_limit` 按 period）→ 真实 ATR / 近 N 日支撑阻力 / MA → 据此算 `entry_low/entry_high/stop_loss/target_price`
   - 拿得到 → 用真实值，`confidence` 用**真实因子**重算（不再用固定 0.45/0.4/0.4）
   - 拿不到 → 退回现有固定系数路径，**保留 `synthetic: true` 与现有标注**
2. **`synthetic` 语义收紧为「真实值也不可得」**，而非现在的「该风格无真实信号」——两者的数据质量完全不同，混用会让 (b) 类永远是假数据。
3. **排序**：`synthetic=true` 的条目在组内**排在真实条目之后**（当前 conf 40 > real 均值 28.5，是反的）。
4. **标记增强**（D4 要求的「标记」）：`risk_notes` 区分两种成因——「数据源不可用」/「信号未达标」，并附上尝试过但失败的数据源名。

- **改动面**：`analysis-engine/src/recommender/strategies/watchlist.rs:235-380` + `mod.rs:740-780` 调用处
- **验收标准**：
  1. 重跑扫描后，`short` 周期 `trend` 风格的真实候选数 **> 0**（若仍为 0，需说明是 (a) 类并在 `risk_notes` 里给出失败数据源）
  2. `synthetic=1` 条目若因 (b) 类产生 → **视为缺陷**（应为 0 条）
  3. `synthetic=true` 恒定 conf 40 的现象消失（conf 随真实因子浮动）或明确保留在 (a) 类
- **风险**：会新增 K 线请求 → 注意**串行 for 的性能问题**（历史上全池 83 只一轮曾达 4 分 15 秒）；`per_code_locks` 已有，但需评估并发

### F-2 ✅ **已实施（2026-09-12，方案 A）**：`MIN_GROWTH = +0.02` 把衰退公司抬成正增长

**用户决策：方案 A** —— 下界改 `−0.30`（与 `compute_graham_value` 对齐）+ 三档缩放改「按方向」。

- **源码级确证**（非推断）：`growth = latest.revenue_yoy.map(|y| y / 100.0).unwrap_or(default_growth).clamp(min_growth, max_growth)`
- 603353 实测 `revenue_yoy = −6.05%` ⇒ 修复前 `growth = +0.02`。**对越差的公司向上偏置越大**
- **同源的 `compute_graham_value` 已于 P1-A 修**：下界 `0.0 → −0.30`，其注释明写
  「把负增长抹平为 0，等于对衰退股默认『零增长』，反而**高估**其内在价值」⇒ 本次补齐 DCF 侧**漏修**
- **「不能只改常量符号」的原因**（这也是选 A 不选 B 的理由）：
  `low_growth = growth × 0.6` 在负增长区间**会变大**（−6% → −3.6%）⇒ 保守档比中性档乐观，
  `low > mid` 的**档位乱序**。原 `MIN_GROWTH = +0.02`（正数）实质上是在**用「禁止负增长」掩盖缩放方向错误**

**实际改动**（`src-tauri/crates/astock-data/src/mcp_tools.rs`）

| 项             | 改前                                                                    | 改后                                                                     |
| -------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `MIN_GROWTH`   | `0.02`                                                                  | **`-0.30`**                                                              |
| `growth` 计算  | 仅 `revenue_yoy` 分支 clamp（`unwrap_or(default_growth)` 分支不 clamp） | **两条分支统一 clamp**                                                   |
| 保守档增长率   | `growth × 0.6`（无条件）                                                | `growth ≥ 0` → `×0.6`；`growth < 0` → **`×1.4`**（向悲观方向）           |
| 乐观档增长率   | `growth × 1.5`（无条件）                                                | `growth ≥ 0` → `×1.5`；`growth < 0` → **`×0.6`**（向乐观方向），再 clamp |
| 保守档缩放下限 | `min_growth / 2.0`（转负后 = `−0.15`）                                  | 显式常量 `MIN_PERPETUAL_GROWTH = 0.0`（**不允许负永续增长**）            |
| 乐观档永续上限 | 内联魔数 `0.05`                                                         | 具名常量 `MAX_PERPETUAL_GROWTH = 0.05`                                   |

> ⚠️ **与 PLAN 原文的偏差**：方案 A 原文写的是**减性**形式 `low_growth = growth − growth.abs() × 0.4`，
> 实装用了**乘性**形式 `growth × 1.4`。两者在 `growth < 0` 域完全等价（`g − |g|×0.4 = g + 0.4g = 1.4g`；
> 对应正增长域 `g − 0.4g = 0.6g`），选乘性只为与既有 `×0.6 / ×1.5` 风格一致、便于并排阅读。

**603353 实测效果**（复算脚本 `dcf-recompute-603353.js`，参数取自运行时 `dcf.assumptions`：
`perpetual = 3% / discount = 10% / years = 5 /` 净利均值 `6918.0 万 ⇒ 锚 6226.2 万 / shares = 170,420,382`）

**影响面（不要误以为只影响衰退股）**

`growth` 的取值由 `max(revenue_yoy, +2%)` 变为 `max(revenue_yoy, −30%)`，故**分三段**：

| `revenue_yoy`                               | `growth` 变化                             | 三档估值变化                                            |
| ------------------------------------------- | ----------------------------------------- | ------------------------------------------------------- |
| `≥ +2%`（含缺省 `default_growth = 12%`）    | **不变**                                  | **完全不变**（`low = 0.6g` / `high = 1.5g` 与改前同式） |

| `< 0%`                                      | 由 `+2%` 降为该值 ⇒ **显著下调**          | 下调 + 缩放方向翻转（保守档更悲观）                     |

**⚠️ 剩余问题：603353 的 `mid` 仍只有 3.61 元（现价 39.25，upside −90.8%）**

修复后 `upsidePct` 由 `−86.9%` 变成 `−90.8%` —— **「深度高估」的结论并未因修复而改变**。
原因是 **DCF 对锚定值线性**：要支撑 39.25 元，需要 `fcf_per_share ≈ 2.78 元`
（= 39.25 / 14.10），而当前锚 `6226.2 万 / 170,420,382 股 = 0.365 元/股` —— **差 7.6 倍**。

即：**603353 的估值分歧主要由「锚定量级」决定，不由增长率参数决定**。而锚定值走的是
**fallback 路径**（`eastmoney` 的 `fcf/ocf/capex` 恒为 `None` ⇒ A 股 DCF **永远**用
「近 5 年报正净利均值 × 0.9」当 FCF 代理）。该代理对**重资产/周期底部**公司会系统性低估 FCF

> `eastmoney` 财报表是否可取 `经营现金流净额`/`资本开支`？若可取，应优先用 `ocf − capex`，
> 而非「净利 × 0.9」。若确实不可取，应在输出的 `basis` 里明确标注代理口径，
> 并让 `value.assessment` 的 prompt 知道「该 DCF 是代理口径，不宜直接当内在价值」。

**回归防护**（新增 3 个用例）
