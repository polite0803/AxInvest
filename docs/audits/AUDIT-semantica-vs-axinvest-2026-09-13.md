## 1. 总判断（本报告最重要的一节）

### 两家的病型

|            | **Semantica**                                                                                                                                                                                                                                                                                                                                                                                | **AxInvest**                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **主病型** | **出口不严型**（+ 亦重入边缺失）                                                                                                                                                                                                                                                                                                                                                             | **入边缺失型**                                                                   |
| 典型证据   | `pipeline/execution_engine.py:692-695` 无 handler 时 `return data` 静默直通；`ontology_validator.py:340-354` 一致性/可满足性校验是 `pass` 占位；`ontology_validator.py:382 check_constraint` 恒 `return True`；`sparql_reasoner.py:294 _has_type` 恒 `return True  # placeholder`；`conflict_detector.py:1383` 解决逻辑自注 `placeholder`；`defender-for-devops.yml:79 --soft-fail` 永不失败 | 参数被声明但无消费点；状态位有读无写；两套判定互不联通（见 MEMORY 铁律 6/13/25） |

> **推论：检法不可互套。** Semantica 的问题在「门存在但放行」，我方的问题在「零件齐但没接线」。用它的「质量门实现」当范本抄 = 用错药。
>
> ⚠️ **但「出口不严」只适用到它的推理层与 pipeline 层 —— 不可下推到本体层。** `semantica/ontology/`（9,298 行）是全仓**唯一**一个「既设计了、又真实现了、还被系统性治理过」的完整子系统，是本仓库质量最高的部分。**整体病型不能下推到单个模块**（详见专项报告 `AUDIT-semantica-ontology-deep-2026-09-13.md` §0/§7）。
