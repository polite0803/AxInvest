## 一、审计方法（可复用）

本轮全部结论都建立在**一个可证伪的方法**上，而不是「读代码觉得不对」：

### 1.1 反解验证法：先证明「我复刻的就是线上跑的公式」

从面板显示的两个比值出发联立反解输入参数：

```
目标比值：high/mid = 1.7737   low/mid = 0.6109
⇒ 反解 growth = 17.78%      （拟合残差 1.60e-5）
⇒ 隐含 FCF/股 = 0.9819 元   （现价 21.02 ⇒ FCF 收益率 4.67%）
⇒ 代入复算 = 24.76 / 40.53 / 71.89  vs 面板 24.76 / 40.53 / 71.89   ← 逐位吻合
```

**为什么必须做这一步**：只有复刻与线上逐位吻合，后续所有敏感度数字才是**真值**而非
「我以为是真值」。本仓已有教训 —— `sci6-after.mjs` 首次运行时给「改动前」套用了**新**的
`high` 上限，算出 44.38 而非真实的 71.89；加 `oldCap` 开关分别复刻新旧逻辑后，
「改动前」才回到 `24.76 / 40.53 / 71.89`。

### 1.2 弹性（elasticity）分解：把「谁最重要」变成可比的数

$$\varepsilon_x = \frac{\partial \ln IV}{\partial \ln x}$$

解析式（两阶段 DCF）与数值差分互校：

| 参数 | 数值 | 解析 | 含义 |
|---|---|---|---|
| `E_d` | **−1.963** | −d/(d−p) | 折现率 ↑1% ⇒ 估值 ↓1.96% |
| `E_p` | 0.783 | p(1+d)/((1+p)(d−p)) | 永续增长率 ↑1% ⇒ 估值 ↑0.78% |
| `E_g` | 0.712 | — | 预测期增长率 ↑1% ⇒ 估值 ↑0.71% |

`|E_d| / |E_p| = 2.51`、`|E_d| / |E_g| = 2.76` ⇒ **折现率是三者中最敏感的**。

### 1.3 分档归因：把区间宽度拆到「哪一维贡献多少」

| 口径 | 结果 | 宽度 |
|---|---|---|
| 仅变 `g`（±档） | 30.82 → 58.27 | 1.89 倍 |
| 仅变 `p`（±30%） | 33.62 → 51.66 | 1.54 倍 |
| 两维同变 | 25.22 → 73.21 | **2.90 倍** |

⇒ 全宽 190.3% **≫ 两维之和 142.7%** —— 是**乘法耦合**，不是线性叠加。
⇒ 且 `d` **完全不在区间内**，尽管它弹性最大。

## 二、发现 1：参数取值无依据，且与模型自身前提冲突

### 2.1 事实

`mcp_tools.rs` 常量区的文档在这轮之前**只论证「四处同步」，不论证「为什么是这个数」**：

| 常量 | 改前 | 该值违反什么 |
|---|---|---|
| `PERPETUAL_GROWTH` | **4.0%** | 模型**自己**申报 `DISCOUNT_RATE = 8.5% = 无风险 2.5% + 风险溢价 6%` ⇒ `p = 4% > r_f = 2.5%` |
| `DISCOUNT_RATE` | 8.5% | 值本身可接受，但**被写成裸数**，与「2.5% + 6%」的分解脱钩 ⇒ 三个数可各自漂移 |
| `MAX_PERPETUAL_GROWTH` | 裸 `0.05` | 文档写「不变量：必须 < `DISCOUNT_RATE`」，但该不变量**只约束两个常量之间的关系**，对**配置通道无任何约束力** |

### 2.2 为什么 `p > r_f` 是硬错误（不是风格问题）

永续增长率进入的是**终值**：`TV = FCF₅ × (1+p) / (d − p)`。
`g_terminal ≤ risk-free rate` 是 Damodaran 的终值约束，其含义是：
**一家公司在永续期不可能长期以高于经济名义增速的速度增长**（否则它会吞掉整个经济体）。
本模型自己在同一份文档里把 `r_f` 申报为 2.5% ⇒ **`p = 4%` 违反自身前提 60%**。

定量后果（300642）：

| `p` | `mid` | 相对现价 | 终值占比 |
|---|---|---|---|
| 4.0%（改前） | 40.53 | +92.8% | 84.4% |
| 2.5%（= `r_f`） | 31.61 | +50.4% | 80.0% |
| **2.0%（改后）** | **29.55** | **+40.6%** | **78.6%** |

⇒ 用户看到的「低估 +92.8%」里，**约 22pp 来自这个无依据参数**。

### 2.3 ⚠ 与 2026-09-12 那次「校准」的历史关系（必须记录）

同一参数在 **11 天内被反向校准两次**：

| 日期 | 动作 | 给出的依据 |
|---|---|---|
| 2026-09-12 | `p` **3% → 4%** | 注释仅一句「接近长期名义 GDP 增速（**原 3% 偏低**）」—— **无参照物、无约束** |
| 2026-09-23 | `p` **4% → 2%** | 模型自身申报的 `r_f = 2.5%` + Damodaran 终值约束 |

**这不是"来回改"，而是两种依据的性质不同**：

- 09-12 的依据是**外部观点**（「GDP 增速大约多少」）—— 没有锚，下一个 AI 可以给出相反的观点，事实上也确实如此；
- 09-23 的依据是**模型内部自洽性**（`p` 与同一文档里申报的 `r_f` 冲突）—— 这是**可判定**的：
  任何人读同一份常量文档都能验证这个矛盾，不需要同意任何观点。

⇒ **教训（写进判据）**：给常量写「取值依据」时，**依据必须是可判定的**。
「原值偏低/偏高」不是依据，它只是把判断本身重述了一遍 —— 而这正是"修了几次都没用"的温床。

### 2.4 改动

```rust
// 拆成具名分量，三者由**编译期断言**锁死（不用运行时测试，不用表达式求和）
pub const RISK_FREE_RATE: f64 = 0.025;
pub const EQUITY_RISK_PREMIUM: f64 = 0.06;
pub const PERPETUAL_GROWTH: f64 = 0.02;          // 原 0.04
pub const DISCOUNT_RATE: f64 = 0.085;
const _: () = assert!(
    { let diff = DISCOUNT_RATE - (RISK_FREE_RATE + EQUITY_RISK_PREMIUM);
      let abs = if diff < 0.0 { -diff } else { diff }; abs < 1e-12 },
    "DISCOUNT_RATE 必须 = RISK_FREE_RATE + EQUITY_RISK_PREMIUM（拆分后三者不得各自漂移）"
);
```

⚠ **为什么用编译期断言而不是写成 `RISK_FREE_RATE + EQUITY_RISK_PREMIUM` 表达式**：

```
0.025 + 0.06 = 0.08499999999999999  ≠  0.085      （差 1.3877787807814457e-17）
```

IEEE754 下两者**不相等**。若把 `DISCOUNT_RATE` 写成求和式，所有按 `0.085` 做 `===` 比对的
门禁与测试会**静默失效**。⇒ 字面量 + 编译期锁等式，是同时满足「单一真相源」与「浮点可比较」的唯一写法。

同时：`MAX_PERPETUAL_GROWTH` 由裸 `0.05` 改锚 `RISK_FREE_RATE`（终值上限不得超无风险利率）。

## 三、发现 2：区间漏掉了弹性最大的那一维（归因错误）

### 3.1 改前的三档定义

```
low  = dcf(g × 0.6,  p × 0.7,  d = 8.5%)      ← 只动 g 和 p
mid  = dcf(g,        p,        d = 8.5%)
high = dcf(g × 1.5,  p × 1.3,  d = 8.5%)
```

**`d` 恒为 8.5%** —— 一个常量。而 §1.2 已证明 `d` 的弹性是 `p` 的 2.51 倍。

### 3.2 后果

| `d` | `mid` | 相对中值 | 终值占比 |
|---|---|---|---|
| 7.5% | 52.58 | +29.7% | 87.6% |
| 8.0% | 45.80 | +13.0% | 86.0% |
| **8.5%** | **40.53** | 0.0% | 84.4% |
| 9.0% | 36.32 | −10.4% | 82.8% |
| 9.5% | 32.88 | −18.9% | 81.3% |

⇒ 仅 `d` ±1pp（相对变动 ±11.8%）就使 IV 从 52.58 走到 32.88，即 **1.60 倍**；
对比 `p` 的**整个 ±30% 档**只给 1.54 倍
⇒ **未申报的 `d` 不确定度 > 已申报的 `p` 不确定度**。

**这是「区间宽度」问题的一个真正来源，但方向与直觉相反**：不是「区间太宽」，
而是**宽度分配错了** —— 把不确定度堆在两个小弹性参数上，同时假装最大的那维是确定的。

### 3.3 「`d` 是唯一能体现公司风险的参数，却是常量」

`d` 在 CAPM 下是 `r_f + β × ERP`。若真的按 β 定 `d`：

| β | `d` | IV | 相对固定 8.5% 口径 |
|---|---|---|---|
| 0.8 | 7.30% | 55.86 | +37.8% |
| 1.0 | 8.50% | 40.53 | 0.0% |
| 1.3 | 10.30% | 28.51 | −29.7% |
| 1.6 | 12.10% | 21.85 | −46.1% |

⇒ 本模型对**所有公司**用同一个要求回报，等于**假设所有公司风险相同**。
这是**口径层的简化**（需产品裁决是否引入 β），本轮**不擅改**（登记 §七）。

本轮只做一件不引入新假设的事：**让悲观情景里「要求回报上升」体现出来**。

### 3.4 改动

```rust
let low_discount_rate = discount_rate + RISK_STRESS_SPREAD;   // RISK_STRESS_SPREAD = 0.01
let (low, _) = dcf_two_stage(fcf_per_share, low_growth, low_perpetual, low_discount_rate);
```

⇒ 悲观档语义由「单参数敏感性下界」改为**悲观情景**：经营假设不利 **且** 要求回报上升。

### 3.5 ⚠ 一个必须说清的反向事实：悲观档**不是**「两维极端相乘」的修正

改前的 `low` 端，其 −38.9% 是「仅 `g` 悲观 −25.3%」与「仅 `p` 悲观 −18.5%」**相乘**的结果：

```
中值 40.53 → 仅 g 悲观 30.26 (−25.3%)  仅 p 悲观 33.02 (−18.5%)  两者同时 24.76 (−38.9%)
```

联合概率 ≪ 单维概率，而正文称它「保守档」⇒ **命名与概率语义不符**。

本轮**没有**把它改成单维极端（那会使安全边际更宽松、掩盖风险），而是：
① 在**悲观方向**再纳入 `d`（§3.4）；② 把 `upsidePct` 的基准改到这一档（§五）。
⇒ 结果是**更严**的判据，而不是更松。**这一点必须明示，否则会被误读为「为了让结论好看而放宽」。**

## 四、发现 3：判据③ 零区分力（作用域错配）

### 4.1 原判据

```rust
if terminal_value_ratio > TERMINAL_RATIO_MAX {   // 0.7
    applicability_signals.push("终值现值占比 …：结论由永续假设独裁");
}
```

它声称检测的是：**「这家公司的估值结论是不是由永续假设独裁」**。

### 4.2 临界点与 `p` 无关（决定性）

复算 `tvr` 跨过 `0.7` 的临界增长率：

| `p` | ③ 的临界 |
|---|---|
| 4.0% | `g > 0.00%` |
| 3.5% | `g > 0.00%` |
| 3.0% | `g > 0.00%` |
| 2.5% | `g > 0.00%` |
| 2.0% | `g > 0.00%` |

逐点验证（`d = 8.5%`）：

| `g` | 旧 `p=4%` | 新 `p=2%` | ③ 命中？ |
|---|---|---|---|
| −30.0% | 44.9% | 44.9% | 不命中 |
| −5.0% | 63.9% | 63.9% | 不命中 |
| **0.0%** | 79.6% | 72.6% | **命中** |
| 17.8% | 84.4% | 78.6% | 命中 |
| 30.0% | 86.5% | 81.3% | 命中 |

⇒ **命中集 ≈ `{g > 0}`** —— 它实际判的是「预测期增长率为**非负**」，
而不是它声称的「结论由永续假设独裁」。**零区分力**。

### 4.3 根因：作用域错配

「估值有多依赖永续假设」由 `1/(d−p)` 这个**全市场统一的常量**决定
⇒ 它是所有标的**共有**的**结构属性**，不可作**逐样本**的适用性判据。

判据①–④ 判的都是**标的的数据形态**（杠杆率、FCF 与净利背离、营收增速、净利符号）；
判据③ 判的是**调用方配置**。**类不同，不能并列。**

### 4.4 这已经是同一判据在一轮内被改两次

| 轮次 | 改法 | 结果 |
|---|---|---|
| 上一轮 | 认为 `growth < 0.0` 合取项导致零命中，删掉 | 删除后变成**恒命中** ⇒ 仍失效 |
| 本轮 | 复算证明临界点落在 `g > 0` 上，与 `p` 无关 | **整体撤销** |

⇒ 两次都是失效，只是失效方向相反（零命中 ↔ 恒命中）。
**教训**：删掉一个合取项之前，必须先算清「剩下的部分单独成立时，命中集是什么」。
本轮才算清 —— 代价是同一判据被改了两轮。

### 4.5 撤销的代价 vs 不撤销的代价

| 方案 | 代价 |
|---|---|

## 五、附带修掉的两处「口径与实算不符」

### 5.1 乐观档上界被自身常量吞掉

```rust
let high_growth = (...).clamp(min_growth, max_growth);   // 改前：上界 = MAX_GROWTH = 30%
```

⇒ `g ≥ 20%` 时 `g × 1.5 ≥ 30%` **被砍回基准档**，而文案仍称「×1.5」：

| `g` | 期望 `g×1.5` | 实际 | 截断 |
|---|---|---|---|
| 10.0% | 15.0% | 15.0% | 否 |
| 17.8% | 26.7% | 26.7% | 否 |
| **20.0%** | 30.0% | 30.0% | **是（临界）** |
| 25.0% | 37.5% | **30.0%** | 是 |
| **30.0%** | 45.0% | **30.0%** | **是（实际乘子 = 1.0，档宽压平）** |

全库 6 条高 `tvr` 样本里 **2 条** `g` 顶在 30%（其中一个被完全压平）。

**改法**：两个上界职责不同 —— `MAX_GROWTH` 围的是**基准预测**（有当期经营数据支撑），
而这里是**按乘子机械展开的情景**，故上界应是「前提上界 × 该乘子」：

```rust
let max_growth_high = max_growth * HIGH_GROWTH_SCALE_POS;   // 0.30 × 1.5 = 0.45
```

### 5.2 `upsidePct` 把「排中间那个假设」当点估计

改前 `upsidePct = (mid − px) / px` —— `mid` 只是「三个任意假设里恰好排中间那个」，
而区间已声明为*非概率区间*（`AUDIT-valuation-param-db-override-2026-09-21.md` §五同源论述）。

⇒ 改为取**保守档**（= 安全边际口径）：「即便按悲观情景重估，现价仍低于该值吗」。

旧口径**不删除**，另存字段（不参与 f5 因子），避免信息丢失。

## 十、方法论产出（写进判据）

1. **全市场统一的参数常量不可作逐样本的适用性判据 —— 作用域错配。**
   判据①–④ 判**标的的数据形态**，判据③ 判**调用方配置** ⇒ 类不同不可并列。
   检法：把该判据的**临界点**解出来，看它实际等价于哪个简单条件。

2. **给常量写「取值依据」时，依据必须是可判定的。**
   「原值偏低/偏高」不是依据（它只是把判断重述一遍）⇒ 下一个 AI 可以给出相反结论，
   事实也确实如此（同一参数 11 天内被反向校准两次）。
   可判定的依据形如：「与同一份文档里申报的 `r_f` 冲突」。

3. **派生常量必须配编译期等式断言，且避免 IEEE754 不等价的浮点求和。**
   `0.025 + 0.06 ≠ 0.085`（差 1.4e-17）⇒ 写成求和式会破坏一切按 `0.085` 比对的 `===` 门禁。
   正解：字面量 + `const _: () = assert!(...)`。

4. **反解验证法**：先由两组比值联立反解输入参数并**逐位复现**显示值，
   再做敏感度分析 —— 否则后续所有数字都是「我以为是真值」。

5. **同一判据在一轮内被改两次 ⇒ 必须记录「演化史」**（§4.4）。
   两次失效方向相反（零命中 ↔ 恒命中）时，说明还没找到临界点。

6. **回算必须分组**（§6.3）：`p` 改动对 `g < 0` 样本完全无效（既有约束已把 `p` 压 0），
   混算中位数会把效应稀释成无意义的数。
