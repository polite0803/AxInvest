# AUDIT — Mover universe 可行性（Phase 0 演练）2026-09-30

> 用途：`PLAN-mover-recall-attribution.md` Phase 0 的实测结论与 universe 决策依据。
> 方法：只读网络探测（`.workbuddy/tmp/crawl_clist.sh`、`probe_throttle.py`、`recovery_probe.py`、`probe_alt.py`、`validate.py`），**未改任何生产代码**。
> 探测本身会改变被测系统状态（见 §4「观测污染」），数字用于定方案形态，不当成长期 SLA。

## 1. 结论一句话

**方案一成立，但主通道必须换成腾讯批量行情**：全市场 5921 只的「当日涨跌幅」用 `qt.gtimg.cn/q=` 批量（80 码/请求）只要 **74 个请求 ≈ 42 秒，实测零失败**；东财 `push2 clist` 只适合单次少量页，连续 60 页必进封禁窗且冷却 ≥5.5 分钟未恢复。

## 2. 实测数据

### 2.1 东财 `push2.eastmoney.com/api/qt/clist/get`（`board.rs:90` 用的就是这个）

| 项 | 实测 |
|---|---|
| 可达性 | 单次请求 HTTP 200、**130–180ms**；`total=5921`（含北交所，B 股未混入）|
| 分页 | **`pz` 服务端硬上限 100**（请求 200/500/1000 一律只回 100 行）⇒ 全市场固定 **60 页** |
| 连续爬取 | 60 页串行（间隔 0.15s）⇒ **仅 11 页成功、49 页失败**，失败形态是连接被断 |
| 封禁范围 | 失败后 `push2` / `17.push2` / `82.push2` / `push2delay` **全部** `RemoteDisconnected`；curl 亦 HTTP=000 ⇒ **按客户端指纹/IP 阻断，不按域名** |
| 冷却 | 150s 后重试失败，再 180s（累计 ≈5.5min）仍失败 ⇒ **恢复下界未知，不作设计依据** |

⇒ 判定：**这条不能当每日主路**。仓里「clist/get 已失效」的注释（`eastmoney.rs:503/3201/3280`）指的是 `push2his` 域，`push2` 域是「能通但一爬就封」，两者要分开记。

### 2.2 腾讯批量行情 `qt.gtimg.cn/q=`

| 项 | 实测 |
|---|---|
| 批量 | bs=50：12/12 成功；**bs=80：8/8 成功**（80 码/请求被完整兑现）|
| 全市场成本 | 5921 ÷ 80 ≈ **74 请求 / ≈42s 墙钟**（0.4s 间隔）|
| 失败 | **0** |
| 字段 | `~` 分隔：f[2]=代码 f[3]=现价 f[4]=昨收 **f[32]=涨跌幅%** |
| 口径互校 | 与东财涨幅榜首页（`fid=f3` 降序）**20 只逐一比对，\|Δ\| 最大 0.0** ⇒ 两源涨幅同口径，可互为降级 |

### 2.3 新浪批量 `hq.sinajs.cn/list=`（需 `Referer: finance.sina.com.cn`）

bs=60：10/10 成功，99 请求 ≈53s；600 只中 **583 只**能算出涨幅（17 只缺昨收 ⇒ 停牌/新股）。可用但**弱于腾讯**，适合当第二降级。

### 2.4 腾讯历史日 K `web.ifzq.gtimg.cn/appstock/app/fqkline/get`

60 只逐票：60/60 成功，请求 120 根实回 120–121 根，**单票 ≈0.53s**。外推全市场：串行 ≈52min，8 并发 ≈7min ⇒ **一次性历史回填可行**（并发放大需重新验风控）。

## 3. 由数据推出的两个设计结论

1. **窗口累计涨幅不需要逐票 K 线。** 只要 `market_daily_close` 逐日落全市场涨跌幅，则
   窗口累计涨幅 = `∏(1 + r_i) − 1`，最大单日涨幅 = `max r_i`——两者都是本地 SQL 聚合。
   K 线通道（§2.4）**只在历史回填时才需要**，不在每日路径上。
2. **每日主路 = 腾讯批量，东财/新浪作降级**。批量大小、请求间隔、退避都必须做成可调（实测 80 可用，但服务端随时可收紧；写死 80 就是把今天的观测当永久契约）。

## 4. 观测污染与未实证项

- **污染**：§2.1 的封禁窗是本次探测（60 页连续 + 多轮重试）触发的；探测结束后未继续等待恢复，**恢复上界未知**。这不改变结论方向（60 页/日不可持续是硬事实），但「安全突发量到底是多少」没测出来。
- **未实证**：腾讯批量在**连续 74 请求**下的真实失败率（本次只跑了 12 与 8 请求的两档，按 600 码外推）；东财 `data.eastmoney.com/bkzj` 板块清单只回 31 条（默认分页，非全板块枚举），故**板块枚举路线本次判废**——`board.rs` 的 `search_concept_boards` 是按关键词搜索，拿不到板块全集，全市场只能靠 clist/行情批量。
- **时点**：全部数字为 2026-09-30 单日本人机器实测；东财风控状态本仓已记录为「累积/速率触发、会随时间收窄或复发」（见 auto-memory [[project-industry-ranking-asof-gap]]），**Phase 1 必须按「随时会红」设计降级，而不是按今天绿设计**。

## 5. 回写 PLAN 的决策

- universe 主通道：`qt.gtimg.cn` 批量（80 码/请求，可配置）；降级链 `hq.sinajs.cn` → 东财 clist 单页。
- `market_daily_close` 的 `change_pct` 直接取批量 f[32]，`close` 取 f[3]、`prev_close` 取 f[4]（停牌/缺值 ⇒ 该票该日**不落行**，不得写 0.0；写 0.0 会让「拿不到」伪装成「没涨」）。
- 采集预算：74 请求 / ≈42s ⇒ 单日一次 tick 足够，无需跨 tick 续爬；但要保留「本轮未采到的票清单」并显式报数，不得静默。
- 历史回填：可选，走 §2.4 通道，判据=回填完成后与批量口径互校抽样 |Δ| 可接受；不放进主路径。
