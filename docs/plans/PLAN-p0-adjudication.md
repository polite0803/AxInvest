## 1. 🚨 更重要的发现：我第一版的结论是错的

### 1.1 错误是什么

第一版基于 `stock_analyses.decision_action` 统计，得出：

> 「全库 27 条有仓位记录中 25 条 = 0%、0 条买入/增持；三只标的动作 3/3 全是减持 ⇒ **输出对输入不敏感 ⇒ 调参是伪工作**」

**这个结论不成立。** 因为我统计的那一层**正是被 P0① 污染的那一层**。

### 1.2 真实分布（链尾 vs 落库）

| 取值层 | 动作分布 |
|---|---|
| **链尾** `portfolio-risk-gate`（真实决策） | **五档齐全**：增持(600031) / 持有(600876) / 观望(688072、301302) / 减持(601166、603353、601231、002837) / 卖出(000980、603290) |
| **落库** `stock_analyses.decision_action` | 27 条中有仓位者 **25 条 = 0%**、最高 8.8%、**增持/买入 0 条** |

**⇒ 决策链有完整分化；把它压成"几乎全是减持"的是落库层，不是决策链。**

### 1.3 决定性对照（同一次运行，两层不一致）

| 标的 | 日期 | 链尾 gate | 落库 `decision_action` | 判定 |
|---|---|---|---|---|
| **600031** | 09-13 | **增持** | **减持** | 🔴 **两套真相**（修复前） |
| **601698** | 09-14 | 减持 / 0% | 减持 / 0% | ✅ **一致**（修复后） |

⇒ **§5.2 的落库修复（09-13）已被 601698 实证验证生效。**

### 1.4 这意味着什么

1. **「调参没用」这个结论可能是对的，但理由完全不同**：不是"输出恒定"，而是**"你看到的是被污染的输出，所以无从判断调参效果"**。
2. **更严重的是**：落库层正是**界面展示的那一层** ⇒ 你对模型质量的长期判断，可能一直在读被污染的读数。
3. 我已经把这条教训写回技能 `scoring-chain-counterfactual-audit`（§「头号陷阱」）：**任何"决策恒定"的统计，必须先在链尾复算一次；两层不一致 ⇒ 先修转发链，再谈决策质量。**

## 3. 本轮新发现的缺陷（未修）

### 3.1 🔴 `hooks.rs` 的 `stock_sector` 静默降级

```rust
let stock_sector = client.get_sector_info(stock_code).await
    .ok()                  // ← Err 被吞，与「无数据」不可区分
    .flatten()
    .map(|s| s.sector_name)
    .unwrap_or_default();  // ← None → 空串
if !stock_sector.is_empty() { /* 只有非空才注入变量 */ }   // ← 空则不注入
tracing::info!(...);       // ← 仅 info，无告警
```

**后果链**：取行业失败 ⇒ 变量**不注入** ⇒ Rhai 侧 `present(stock_sector)=false` ⇒ `sector_is_financial=false` ⇒ **行业豁免静默失效** ⇒ 银行股重新命中 `debt>85 && growth<0` ⇒ 极高风险 ⇒ 跨档压成「减持」。

**与 `portfolio_cash`（无条件注入）对比**：同为注入变量，一个无条件、一个条件式，**这个不一致本身就是信号**。

**历史实情**：09-09 起 19/19 注入成功，**未观察到实际失败** ⇒ 严重性 = 「无告警的静默降级」，不是当前故障。
**建议**：`.ok()` → 显式 `Err` 分支；空值也注入（`None`/空串）+ 降级为 `warn!`。**成本小、无行为风险。**

### 3.2 ⚠️ 方法论错误（已写回技能）

见 §1。教训：**统计前先确认取值层；链尾 ≠ 落库时，先修转发链。**
